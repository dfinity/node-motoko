# AGENTS.md

`motoko` is an npm library that compiles and runs Motoko smart contracts in Node.js or the browser.

## Build, test, format

- Install: `npm ci`
- Build: `npm run build` (runs `tsc -p .`; compiles `src/` to `lib/`, which is required at runtime by `index.js` / `interpreter.js`)
- Test: `npm test` (Jest via `ts-jest`; tests live in `tests/`)
- Bundle size check: `npm run size-limit`
- Format: Prettier. There is no standalone lint/format script; formatting runs automatically on commit via `lint-staged` (see below).

Run `npm run build` before `npm test` if you rely on generated output, since `index.js` and the generator read from `lib/`.

## CI expectations

- `tests.yml`: `npm ci`, `npm run build`, `npm test` on Node.js 22.x and 24.x. Keep both green.
- `size.yml`: enforces bundle size limits on PRs (config under the `size-limit` key in `package.json`).
- A `pre-commit` husky hook runs `lint-staged`, which applies `prettier --write` to `{lib,contrib,utils}/**/*.{js,ts,jsx,tsx}`.

## Directory map

- `src/` — TypeScript source (the only hand-written library code that gets compiled).
- `lib/` — TypeScript build output. Generated by `npm run build`; not committed. Never hand-edit.
- `utils/generate.js` — script (`npm run generate`) that downloads the Motoko compiler, core package, and error codes.
- `contrib/` — editor/tooling integrations (syntax highlighting, Monaco, snippets).
- `versions/latest/`, `packages/latest/`, `contrib/generated/` — generated artifacts produced by `npm run generate`. Do not hand-edit; regenerate instead.
- `tests/` — Jest test suite. `examples/` — runnable usage examples.

## Conventions and gotchas

- Prettier config (`.prettierrc`): single quotes, semicolons, 4-space indentation, trailing commas everywhere, bracket spacing. Match it or the pre-commit hook will rewrite your changes.
- The bundled compiler and packages under `versions/`, `packages/`, and `contrib/generated/` come from `npm run generate <moc_version> <core_version>`; edit the generator or re-run it rather than editing outputs by hand.
- `.npmrc` sets `min-release-age=7`, so newly published dependency versions are not installed until they are 7 days old.
- Publishing is automated: bumping the `version` field in `package.json` on `main` triggers `publish.yml` to build, test, and publish to npm. Do not publish manually.
- To run `npm run generate` for error codes, set `MOTOKO_REPO` to a local Motoko checkout (defaults to `../../motoko/`).
